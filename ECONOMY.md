# Economy 26.3 Velocity-CTD fork

This branch, `economy/26.3-seamless`, tracks GemstoneGG/Velocity-CTD's default branch. `origin` is `PiyushLAMAO/Velocity-CTD`; `upstream` is `GemstoneGG/Velocity-CTD`. The fast-transition implementation came from CTD pull request #1004, which upstream closed as research. The Economy changes make its comparison conservative and opt-in.

Set `advanced.fast-server-switch = true` only in the isolated test proxy's `velocity.toml`. A server switch can stay in PLAY when the destination's registries (including NBT values and IDs), tags, enabled features, and known-pack offer match what the client holds. NBT compound key order and registry/tag map order do not matter. Missing state, mismatches, and unclassified configuration packets use the ordinary reconfiguration path. Unknown raw packets refuse the destination connection. The default remains `false`.

The 26.3 localhost lab on 28 September 2026 passed a headless Spawn→Overworld→Nether→End→Spawn route through the isolated CTD proxy: five JoinGame packets, zero StartConfiguration packets, and four compatible fast-transition log entries. The fork's proxy check task passed. The 26.3 scoreboard objective and team packet IDs were checked against the pinned 26.3 MCProtocolLib codec (`0x6C` and `0x6F`). These results do not establish real-client visual quality, movement, collision, inventory, or portal correctness. A real-client session is required before calling travel screen-free or seamless in gameplay. The regular proxy remains separate.

The same opt-in fast switch now has a narrower **1.21.11, 26.1/26.1.1/26.1.2, 26.2 and 26.3 Spawn↔Overworld screen-free path**. It is used only when the configuration snapshot matches, the client stayed in PLAY, both backends identify the same dimension, and the transfer is specifically between `spawn` and `overworld`. It withholds the destination JoinGame/Respawn, clears tracked entities and old UI/player state, remaps the backend's player entity ID to the client's retained ID, acknowledges world load to the backend, and filters chunk-wait loading events for the first 20 seconds. Other routes keep their existing transition behavior. On failure, disable `advanced.fast-server-switch` in the isolated test proxy to use normal Velocity transfers.

The packet cleanup adapts GPL-3.0 [Conduit](https://github.com/tame-gg/conduit) source at `d5176e5`, with attribution retained in the copied packet classes. The 26.3 packet IDs were counted from the local Mojang-mapped `GameProtocols.CLIENTBOUND_TEMPLATE`; the earlier IDs follow the Conduit registry. The supported clients map to four protocols: 1.21.11 = 774, 26.1/26.1.1/26.1.2 = 775, 26.2 = 776, and 26.3 = 777. The cleanup mappings are covered by `SeamlessPacketRegistryTest` and must be rechecked when Minecraft changes its protocol. With the old JAR, a localhost protocol-777 bot saw two JoinGame packets, one Respawn and no StartConfiguration on Spawn→Overworld. With the current JAR, a protocol-774 bot completed Spawn→Overworld→Spawn with both backends accepting the player, one initial JoinGame, zero Respawn and zero StartConfiguration; CTD logged both screen-free directions. A protocol-777 bot completed the same round trip with the same packet counts. A real 1.21.11 client traversed Spawn→Overworld, CTD logged the route, Overworld accepted the player, and the operator reported that the loading screen was gone. The same real 1.21.11 client later confirmed the Overworld→Spawn return trip had no loading screen and movement at Spawn worked. A real 26.2 client also traversed Spawn→Overworld→Spawn on the isolated CTD proxy; CTD logged both screen-free directions and the operator reported no loading screen and working movement in both destinations. Protocol-level bots for 775 and 776 each completed the same round trip with one initial JoinGame, zero Respawn and zero StartConfiguration. The 774 bot passed again on this build. The 777 bot also passed both directions on this build with one initial JoinGame, zero Respawn and zero StartConfiguration; CTD logged both screen-free routes. The real-client visual result for each 26.1.x release and separate chunk-rendering, entity, inventory and interaction checks remain open. `:velocity-proxy:check` and `:velocity-proxy:shadowJar` passed with 251 proxy tests and no failures. The isolated test JAR SHA-256 is `021078E2477B424B54E7C521069502D7DF2BE091CEA5108FBE40F0AFC159610F`. The regular proxy on port 25690 has not been replaced.

Restart limbo remains outside this fork. The existing InsaneReconnect plugin already owns bounded waiting, backend health checks, and gradual reconnect. Moving that policy and a virtual world into CTD would enlarge the proxy patch and make upstream updates harder. The pinned LimboAPI dependency still needs a 26.3 port and acceptance test before this plugin can be enabled in the Economy lab. CTD's ordinary fallback can redirect to a live backend; it is not a limbo hold.

To update after CTD changes, run `scripts/update-economy.ps1` from any PowerShell directory. It checks that this feature branch has no uncommitted changes, fetches CTD's current default branch, merges it, and runs `:velocity-proxy:check` and `:velocity-proxy:shadowJar`. If Git reports conflicts, resolve them in this fork, rerun those tasks, and repeat the 1.21.11/26.1.x/26.2/26.3 packet-ID and protocol-transfer checks, plus real-client checks, before pushing. The script never copies runtime files or deploys a proxy. After validation, push with `git push origin economy/26.3-seamless`.
